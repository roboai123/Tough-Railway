Architecture & Deployment Guide

Tough Railway Platform Documentation

Complete technical guide on file modularity, adding 10,000+ questions, changing exam rules, and deploying to GitHub Pages.

1. Modular Architecture Overview

The application is engineered as a unified single-page architecture that cleanly separates data configurations from view logic.

  • questionsDB: JavaScript array storing structured questions with IDs, subjects, options, correct answers (0-indexed), explanations, and difficulty ratings.
  • testConfigsDB: Test configurations setting total duration (minutes), marks per correct answer (+1), and negative marking (-0.33).
  • CBT Engine (cbtState): Isolated engine managing timer countdowns, answer states, question palette markers, and local storage state.

2. How to Add New Questions

To add new questions, simply push a new JavaScript object into the questionsDB array: 

{
    id: 21,
    exam: "RRB NTPC",
    subject: "Mathematics",
    chapter: "Time and Work",
    question: "A can finish a job in 10 days, B in 15 days. How many days working together?",
    options: ["5 days", "6 days", "8 days", "12 days"],
    answer: 1, // 0-indexed index (6 days is option index 1)
    explanation: "1/10 + 1/15 = 5/30 = 1/6. Total days = 6.",
    difficulty: "Easy",
    year: "2024"
}

3. How to Deploy on GitHub Pages

  1. Create a public GitHub repository named tough-railway.
  2. Upload this index.html file to the repository's root folder.
  3. Go to Repository Settings > Pages.
  4. Under Source, select main or master branch and click Save.
  5. Your website will be live at https://YOUR_USERNAME.github.io/tough-railway/.

4. Firebase & Backend Scalability

The platform functions completely offline and static via localStorage. When you are ready to expand to cloud database storage:

  • Replace localStorage.setItem() calls in saveTestResultToStorage() with Firestore addDoc().
  • Replace handleDemoLogin() with Firebase signInWithPopup() or signInAnonymously().
